# DDR-001: the parent reply-activity summary, built by bolt.new

## Task

Implement `FEATURES.md` rows **E19 through E23** — the read-only parent summary
showing how many coaches have been contacted, how many have replied, which ones,
an empty state in words, and suppressed counts when the server cannot be
reached — inside `index.html`, `styles.css`, and `app.js`. No new endpoint, no
new storage; the data already exists behind `GET /entries`.

The delegation was the whole feature, not a fragment of it. The prompt was the
five context files plus the three page files plus one instruction line:
*"Implement the feature marked in FEATURES.md, in these three files only. Follow
STYLE.md and STANDARDS.md. Do not add dependencies. Ask before changing anything
else."*

## Tool and model

**bolt.new**, free tier, project `sb1-hw9wmzcv`, 2026-09-29. bolt did not report
a model name in its interface and I did not find one in the output; the zip
declares only its template, `bolt-vite-react-ts`. Recording "not reported"
rather than guessing.

have discovered by building it myself. I am recording that as a real return while
noting it is not the return the time column measures.

## Trust Boundary

**What crossed.** My PROJECT.md, FEATURES.md, STYLE.md, STANDARDS.md, TOOLS.md,
and all three page files went to bolt.new's servers, 58 KB in one paste. That
includes the business framing of Connexus, the specification, and the deployed
Worker URL in plain text. It does not include any athlete's data, because the
data lives in D1 and only the URL crossed. **I am accountable**: bolt was given
the address of an endpoint that ADR-002 records as having no authentication, so
anything that can read that paste can read every entry in the database.

**Reverse crossing — what came back in.**

1. **Nineteen npm dependencies** in a `package.json` I did not ask for, including
   `@supabase/supabase-js`, a client for a hosted Postgres service this project
   does not use, plus React, React DOM, Tailwind, TypeScript, Vite, ESLint, and
   `lucide-react`. The instruction line said not to add dependencies.
2. **A complete React/Vite scaffold** — `src/App.tsx`, `src/main.tsx`, four
   `tsconfig` files, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`,
   `eslint.config.js`, and a `package-lock.json`.
3. **Three meta tags injected into `index.html`** pointing the page's social
   preview image at `https://bolt.new/static/og_default.png`. My page would have
   advertised bolt every time anyone shared the link.
4. **A hidden instruction file, `.bolt/prompt`**, shipped inside the deliverable.
   It reads in part: *"For all designs I ask you to make, have them be beautiful,
   not cookie cutter"* and *"this template supports JSX syntax with Tailwind CSS
   classes, React hooks, and Lucide React for icons."* This is a **second set of
   instructions competing with mine**, which I did not see until I unzipped the
   output. It contradicts STANDARDS.md rule 7 directly, and it is the most
   plausible explanation for both item 1 and for bolt ignoring my STYLE.md
   tokens: a tool told to be beautiful rather than to follow a token file will
   prefer its own palette.

Licenses were not reviewed. No telemetry was inspected. Both are gaps.

## Findings

**EARS rows passing: 5 of 5.** My committed prediction was 3 of 5, made before
bolt saw the spec and resolved without editing it. I was wrong about which rows
were at risk: I assumed the two "SHALL NOT" rules would be missed, and bolt
handled both, inventing a `lastLoadFailed` flag to distinguish "no entries" from
"could not check" — a distinction E23 required and did not explain how to build.

**Failures and what I changed:**

- Removed the three bolt.new meta tags from `index.html`.
- Did not copy the scaffold or the nineteen dependencies into the repository;
  only the three files were carried over.
- Left bolt's `#45586b` and `#e0e0e0` in place for now and recorded them as
  STYLE findings in `JUDGMENT.md` Q8 and Q9, rather than quietly fixing them and
  losing the evidence that the tool ignored the token file.

**Could not fully verify, and what I did about it:**

- **The nineteen dependencies.** I audited none of them. I removed them by not
  copying the scaffold, which is avoidance rather than verification. If a future
  delegation needs any of those packages, the audit is still owed and TOOLS.md
  would need a row before installing.
- **`.bolt/prompt`.** I can read what it says but cannot know how much of the
  output it shaped, because I cannot run bolt without it. The causal claim above
  is a hypothesis consistent with the evidence, not a measurement. What I did:
  preserved the file unmodified inside `delegated/bolt-001.zip` so a reader can
  check my reasoning against the artefact.
- **Whether bolt's code is correct under inputs I did not try.** Five rows passed
  under the cases I constructed. I did not test a coach named with markup, a
  hundred entries, or two statuses changing at once. What I did: recorded the
  coverage honestly in `EVALS.md` section 3, where E19 and E20 are marked as
  checked through the data rather than through the summary itself.
